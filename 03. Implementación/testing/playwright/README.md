# Testing E2E — Bajoneá (Fase 17)

Suite de Playwright + TypeScript contra el frontend y el backend reales de Bajoneá, corriendo contra una base de datos propia (`bajonea_test`), separada de `bajonea_final` (desarrollo).

## Antes de correr la suite

El backend de test y el de desarrollo (`bajonea`, `bajonea_practicas3`) no pueden compartir puerto. Los scripts de esta carpeta **nunca matan un proceso que no hayan levantado ellos**: `scripts/entorno-test.mjs` guarda los PID de lo que levanta en `%TEMP%/bajonea-entorno-test.json` y solo detiene esos; si el puerto elegido ya está ocupado, aborta. Los puertos son configurables (`PUERTO_BACKEND`, por defecto 8080, y `PUERTO_FRONT`, por defecto 5501).

**La contraseña de `admin@bajonea.ar` en `bajonea_test` se define solo con la variable de entorno `ADMIN_PASSWORD`** (no hay ningún valor escrito en el código ni en este README). La leen los helpers de Playwright, `entorno-test.mjs` y los estreses; los runners `correr-newman.mjs` y `correr-estreses.mjs`, si la variable falta, la toman en memoria de `admin_password` del environment de Postman sin imprimirla, y si ninguna fuente la tiene fallan con un mensaje claro. En `bajonea_test` conviene que sea la misma que `admin_password` del environment de Postman.

**Atajo para dejar todo listo desde cero** (detiene el entorno propio anterior, resetea `bajonea_test`, levanta el backend en perfil `test` y el frontend, y fija la contraseña del administrador desde `ADMIN_PASSWORD` por el flujo real de recuperación):

```bash
export ADMIN_PASSWORD=...        # la contraseña del administrador de test
PUERTO_BACKEND=8081 PUERTO_FRONT=5502 bash testing/playwright/scripts/preparar-entorno-test.sh
node testing/playwright/scripts/entorno-test.mjs detener   # al terminar (con los mismos puertos)
```

Con un backend que no es el 8080, el frontend se sirve desde una copia temporal con el puerto cambiado en `js/api.js` (el original fija `http://localhost:8080`). Después, para correr contra esos puertos: `E2E_API_BASE_URL=http://localhost:8081/api/v1 E2E_FRONTEND_URL=http://localhost:5502 npx playwright test`. El backend escribe su log en `%TEMP%/backend-test.log` (`BACKEND_LOG` para cambiarlo) con `--logging.file.name`, que es lo que leen los estreses para contar `Deadlock found` y `Lock wait timeout`.

**Cambios en el frontend con un backend en otro puerto.** La copia temporal que se sirve se hace una sola vez al levantar. Después de tocar `frontend/`, regenerarla sin reiniciar nada con `PUERTO_BACKEND=8081 PUERTO_FRONT=5502 node testing/playwright/scripts/entorno-test.mjs refrescar-front` (usa los mismos puertos que `levantar`; solo toca la carpeta temporal registrada). Al correr Playwright hay que pasar siempre `E2E_FRONTEND_URL`: sin ella la configuración levanta un servidor propio en el 5501.

Los mismos pasos, a mano:

1. **Resetear `bajonea_test`** (`npm run test:reset`): recrea la base vacía, aplica el schema físico de `bajonea_final` (`V1__baseline_bajonea_final.sql`, directo vía `mysql`), el catálogo geográfico (seed del ETL de Georef), levanta el backend una vez para que Flyway baselinee V1 y aplique V2 en adelante, y siembra `admin@bajonea.ar`, que queda con una contraseña desconocida (gap real de `V1`, ver `docs/DECISIONES.md`, 2026-09-02). Tarda unos 30 s. Es un paso manual: no corre solo antes de cada `npm test`.
2. **Levantar el backend con el perfil `test`** contra `bajonea_test` (`./mvnw spring-boot:run -Dspring-boot.run.profiles=test` desde `backend/`, o `entorno-test.mjs levantar`).
3. **El frontend** lo levanta `playwright.config.ts` con un `webServer` solo si se usa el puerto por defecto 5501; con otro puerto (`E2E_FRONTEND_URL`) hay que tenerlo servido (`entorno-test.mjs` lo hace).

**Fuentes y reportes (bloque A5 de E3).** Todos los specs importan `test` y `expect` de `tests/helpers/prueba.ts`, que bloquea el CSS y las fuentes de Google Fonts en cada contexto del navegador (el layout usa siempre la fuente de respaldo y no depende de internet; `BLOQUEAR_FUENTES=0` lo apaga). La configuración graba `trace`, video y captura solo al fallar (`retain-on-failure`) y escribe `reportes/resultados.json` (reporter JSON con la duración de cada test; `PW_JSON_OUTPUT` cambia la ruta) además del HTML (`open: 'never'`). `node scripts/analizar-duraciones.mjs [archivo] [cuántos]` lista los specs y los tests más lentos, el mayor hueco sin actividad entre dos tests (sospecha de suspensión de la máquina) y los tests de más de 120 s. Un `--reporter` por línea de comandos reemplaza a los de la configuración. El día y la hora que usan los tests salen de la zona `America/Argentina/Ushuaia` (`E2E_ZONA_HORARIA`), no de la de la máquina.

## Correr la suite

```bash
npm test              # toda la suite, headless
npm run test:ui       # modo UI interactivo (recomendado mientras se escribe un spec)
npx playwright test tests/01-registro-y-verificacion.spec.ts   # un spec puntual
npm run report        # abre el último reporte HTML
```

**Proyectos:** `npm test` y `npx playwright test` corren solo `chromium` (escritorio). WebKit (emulación de iPhone 13, 390×844) tiene su propia configuración, `playwright.webkit.config.ts`, y se corre con `npm run test:webkit`. **No corre en la máquina de Diego:** Windows bloquea 4 DLL del navegador con una directiva de Control de aplicaciones (ver `docs/APRENDIZAJES-TECNICOS.md`); probar en otra máquina o en un iPhone real. Para WebKit conviene sumar solo los specs de UI, no el `21` ni el `22` (son de API).

`playwright.config.ts` fija `workers: 1` siempre (no solo en CI) -- la suite corre en serie
por defecto, sin necesidad de pasar `--workers=1` a mano. **Es configuración permanente del
proyecto, no una limitación temporal ni una opción de performance:** `admin@bajonea.ar` es una
cuenta real compartida por 43 de los 50 archivos de spec (vía `fijarPasswordAdminYLoguear`,
`tests/helpers/backend.ts`) y Bajoneá tiene sesión única por cuenta, así que con más de un worker
dos specs pueden pisarse la recuperación de contraseña de esa cuenta y romper al que pierde la
carrera. Además el backend único de desarrollo y Cloudinary no toleran esa concurrencia --
confirmado real: con paralelismo por defecto fallaban ~45 tests. Ver `docs/DECISIONES.md`,
entrada del 2026-09-25.
